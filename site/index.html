01

The philosophy

Vibe coding is fast.
Software engineering is cumulative.

Prompts create momentum. Engineering creates continuity. Canon is the bridge: a durable layer of context that survives the chat, the agent, and the next rewrite.

01

The repository remembers

Knowledge lives beside the code in plain, reviewable Markdown—not inside a disappearing conversation.

02

Records drive the work

Agents retrieve the relevant meaning, requirements, and decisions before they plan or change code.

03

Change stays explicit

Records are not rigid law. When direction changes, the history is amended or superseded instead of silently forgotten.

02

One corpus, three questions

Give every agent the same source of truth.

Canon manages a connected corpus of project records. Each kind has a narrow job, a stable identity, and a lifecycle that can evolve.

03

The agent loop

Context becomes part of the build loop.

Canon is designed for agents to operate directly. Commands are discoverable, reads are structured, and every mutation can be previewed before it touches the corpus.

✦

Titles route attention. Full records provide the grounding. An agent uses both.

  1. 01

    Discover

    Inspect the available commands and the health of the project corpus.

    canon doctor
  2. 02

    Retrieve

    Find the records that govern the area, then read them in full.

    canon search --query "auth"
  3. 03

    Plan & build

    Let accepted language, behavior, and decisions constrain the change.

    canon show --id ADR-0007
  4. 04

    Record

    Preview new knowledge, apply it, and keep the corpus current.

    canon adr new … --dry-run

Start with the repository

Install the memory
where the work happens.

Canon is a small, dependency-free Go CLI. Its records stay portable, diffable, and owned by your project.

quick-start.sh 
$ go install github.com/victorhsb/canon/cmd/canon@latest
$ cd your-project
$ canon commands
$ canon doctor
